# BE-006. Приватное S3 и управление файлами

> Прежний расширенный план. Для первой версии этот файл не выполнять: использовать [новый реестр MVP](../README.md) и [summary.md](../../docs/backend/summary.md). Полезные проверки можно переиспользовать в пределах новых заданий; полный объём и прежние зависимости больше не обязательны.


Статус: SUPERSEDED для первого MVP. Приоритет: P1. Зависимости: BE-004, BE-005.

## Контекст

Прочитать [обзор архитектуры](../../docs/backend/README.md) и связанные спецификации. Это отдельное задание для последующего агента, не отчёт об уже выполненной реализации.

## Объём

Ввести storage protocol и S3 adapter с private bucket в российском регионе, object keys без ПД, metadata/checksum, короткими download URL. Создавать document_files состояния pending/ready/failed; reconcile orphan/missing objects, lifecycle temp/multipart. Разделить app и backup credentials. Локальный adapter допускается только в dev/test. Использовать provider free tier лишь после проверки доступности/условий аккаунта.

## Результат и приёмка

Чужой файл нельзя получить через API; bucket не публичен; ссылки истекают; повторный put/reconcile не создаёт бесконтрольных копий; files относятся к конкретной версии.

## Проверка

S3-compatible integration: put/head/get/delete, expiry, отказ доступа, сбой put→commit, missing object recovery.

## Область изменений

app/services/storage, file API, конфиги; в БД хранить key, не presigned URL.

Не менять визуальный дизайн без необходимости задачи; не делать deploy/покупку/боевой платёж автоматически.
