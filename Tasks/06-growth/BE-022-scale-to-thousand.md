# BE-022. Масштабирование по метрикам до 1000 пользователей

> Прежний расширенный план. Для первой версии этот файл не выполнять: использовать [новый реестр MVP](../README.md) и [summary.md](../../docs/backend/summary.md). Полезные проверки можно переиспользовать в пределах новых заданий; полный объём и прежние зависимости больше не обязательны.


Статус: SUPERSEDED для первого MVP. Приоритет: P2. Зависимости: BE-021.

## Контекст

Прочитать [обзор архитектуры](../../docs/backend/README.md) и связанные спецификации. Это отдельное задание для последующего агента, не отчёт об уже выполненной реализации.

## Объём

Проверить сценарий 1000 registered и отдельно предполагаемые DAU/concurrent jobs. По измерениям выбрать вертикальный upgrade, дополнительные LLM slots, отдельный render VPS или managed PostgreSQL. Подготовить миграцию/rollback, пересчитать полную стоимость и RPO. Не добавлять K8s/микросервисы без доказанной необходимости.

## Результат и приёмка

До/после benchmark показывает улучшение конкретного bottleneck; файлы доступны между workers; нет двойной обработки/списания; месячный бюджет и recovery подтверждены.

## Проверка

Load profile с burst, provider quotas, DB EXPLAIN/pool, cold restart, multi-worker lease tests.

## Область изменений

infra/config/capacity ADR; социальный вход/рефералки/подписки — отдельный последующий backlog.

## Передача результата

Обновить статус в [реестре](../README.md), описать миграции/конфиги и выполненные проверки с результатами. Если внешних реквизитов/договоров нет, отделить готовый код и sandbox от блокируемого боевого запуска. Не отмечать DONE по одному наличию файлов или mock-тестов. Не менять визуальный дизайн без необходимости задачи; не делать deploy/покупку/боевой платёж автоматически.
