# 01. Аудит текущего состояния

> Актуальный MVP: [summary.md](summary.md), [рефералка/прогресс](10-referrals-and-progress.md), [зарубежные API/бесплатный тест](11-foreign-api-and-free-prototype.md) приоритетнее этого расширенного документа. Реферальный бонусный баланс обязателен; покупка кредитов/промокоды не нужны. Российские LLM исключены. Старые предложения по paid wallet, S3 работ, PDF и масштабированию отложены. Аудит безопасности и применимые юридические обязанности сохраняются.


Проверены исходники в текущем checkout 01.11.2026, а не развёрнутый production. Публичный сервер, реальные ключи, договоры и настройки кабинетов провайдеров не проверялись. Наличие unit-тестов не доказывает работоспособность реальной интеграции.

## Найденные исходные документы

- `docs/PRD.md`: React/Vite + FastAPI + PostgreSQL + Celery/Redis; JSON AST → python-docx; упомянуты ЮKassa/CloudPayments.
- `docs/DB_SCHEMA.md`: пользователи, работы, задачи, история промптов, транзакции.
- `docs/PROMPT_PIPELINE.md`: последовательность генерации.
- `docs/TASKS.md`: многие интеграции отмечены выполненными, хотя фактическая реализация содержит заглушки.
- `instruction.md`: ссылается на `frontend`, где сейчас нет исходного приложения, и на неверный путь Celery. Реальный `package.json` и `src/` находятся в корне.
- `.antigravityrules`: противоречит проекту, требуя Next.js при фактическом Vite.

В проверенных продуктовых документах и исходниках не найдено конкретного предложения PDF API с 50 запросами в день. Это не исключает упоминания в другом чате или удалённой версии. Не считать этот лимит подтверждённым.

## Реальная готовность

| Область | Факт в исходниках | Решение |
|---|---|---|
| Точка входа UI | `src/App.tsx` экспортирует `src/redesign/Studio.tsx` | Подключать именно Studio, старые компоненты не считать действующим продуктом |
| Работы в UI | Studio хранит список в `localStorage`, прогресс растёт по таймеру, план строится локально | Серверные документы/версии/jobs; браузер оставляет только временное состояние формы |
| Пользователь и баланс | `useUserStore.ts` содержит демонстрационного Ивана и локальные add/deductCredits | Профиль и баланс только из API; mock-режим явно отделить |
| Вход и восстановление | В UI нет законченного подключения к реальной auth API | Полный поток регистрации, подтверждения, входа, выхода и сброса |
| DOCX/PDF UI | `docxExport.ts` и `pdfExport.ts` создают клиентский документ по метаданным; PDF открывает печать HTML | Оба серверных файла из одной сохранённой версии AST |
| Auth API | Есть register/login/me и bcrypt/JWT | Сохранить основу, переработать сессии и защиту |
| База | SQLAlchemy модели и Alembic env есть | В `alembic/versions` нет миграций; создать и проверить initial migration |
| Генерация | Есть реальные HTTP-вызовы LLM, сервисы шагов, checkpoints | Интеграция с UI, измерения, идемпотентность и восстановление ещё нужны |
| DOCX | Есть Python-компилятор и тесты OpenXML | Сохранить, дополнить визуальной проверкой PDF/Word |
| Оплата | `payment_service.py` генерирует случайный payment ID и фиктивный gateway URL | Полностью заменить адаптером реального провайдера |
| S3 | `file_s3_url` фактически получает локальный путь в uploads | Ввести storage adapter и object key; bucket пока не подключён |
| Деплой | В корневом наборе нет Docker Compose/production runbook | Добавить воспроизводимую инфраструктуру |

## Блокирующие дефекты

1. **P0 — Поддельные платежи.** В `app/api/v1/endpoints/payments.py` подпись проверяется только если передан `X-Signature`. Без заголовка payload может инициировать зачисление по известному ID. Нет обязательной серверной сверки с эквайером. Текущая схема не соответствует уведомлениям ЮKassa. До исправления не выставлять этот endpoint в интернет.
2. **P0 — Утечка работ.** `websockets.py` принимает WS и SSE по `doc_id` без аутентификации/проверки владельца; события могут включать AST. UUID не заменяет авторизацию.
3. **P0 — Общий известный JWT secret.** `config.py` содержит фиксированный ключ и восьмидневный access token. Нужны обязательные production secrets и отзыв сессий. Не переносить этот ключ в production.
4. **P0 — Потеря кредитов.** `documents.py` сначала вызывает `spend_credits`, который сам делает commit, затем отдельно сохраняет документ и публикует Celery job. Сбой между этапами оставляет списание без работы; повтор запроса списывает снова.
5. **P1 — Гонки генерации.** Resume разрешён и для текущей генерации; нет уникальности активного job/версии и lease. Одновременные job/spot-правки способны перезаписывать AST.
6. **P1 — Неполное resume.** `generation.py` заново генерирует outline даже после восстановления, не сохраняет утверждённый план как отдельный снимок; главы пропускает по количеству. Новый план может расходиться с уже написанным.
7. **P1 — Слишком раннее completed.** Pipeline завершает AST и ставит completed до подготовки DOCX/PDF. Download синхронно компилирует DOCX в API; результат не соответствует смыслу «файлы готовы».
8. **P1 — Списание при ошибке spot.** Кредит списан до проверки/LLM/компиляции; компенсация не реализована, исключения возвращают внутренний текст.
9. **P1 — Auth abuse.** Нет подтверждения email, recovery/logout/отзыва сессий и rate limits; 10 бесплатных кредитов выдаются при каждой регистрации. bcrypt молча обрезает пароль до 72 байт при допускаемых 128 символах.
10. **P1 — Денежная модель.** Суммы принимаются как float; provider ID не уникален на уровне БД; нет reserve/capture/release, доказуемой истории возвратов и фискализации.
11. **P1 — Проверки не production.** `tests/conftest.py` использует SQLite in-memory и `create_all`: не проверяет PostgreSQL FOR UPDATE, реальные миграции, перезапуск брокера, конкурентные webhook и двойную доставку задач.
12. **P2 — Эксплуатация.** Не заданы retention, offsite backup/restore, квоты, алерты и бюджет. Python requirements имеют открытые нижние границы; импорт bcrypt прямой, зависимость получается транзитивно; в ветке Celery встречается `nest_asyncio`, не объявленный в requirements.

## Что не переписывать

Не менять FastAPI на другой фреймворк ради стоимости. Не переносить всё на Next.js из-за старого правила. Сохранить AST, Pydantic/Zod, полезные тесты и DOCX handlers. Удалять старые frontend-компоненты только после проверки импортов и переключения Studio. Стоимость исправления связности ниже стоимости нового стека.

Проверка тестов и ограничения её результата фиксируются в [verification.md](verification.md). Задания с приоритетом P0 — обязательные условия даже бесплатной внешней беты.
