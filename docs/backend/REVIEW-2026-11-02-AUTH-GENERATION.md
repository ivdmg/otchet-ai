# Проверка продукта и доработка входа — 02.11.2026

## Итог

Локальная авторизация, личные разделы, план и моковый checkout доработаны. Для самостоятельного закрытого тестирования интерфейс готов. Полный живой цикл пока НЕ принят: один реферат на 8 страниц остановился на 75% из-за Groq HTTP 403 на заключении. Word/PDF именно этой работы не созданы. Нельзя считать это успешной генерацией или готовностью к публичному production.

Приложение запущено: http://127.0.0.1:5173/ . API и worker перезапущены с текущими изменениями. Секреты не выводились, платные провайдеры не подключались.

## Сделано

- Удалён зашитый демо-профиль с Иваном Ивановым, почтой, вымышленным балансом и рефералами.
- Личные работы, профиль и реферальная программа показывают гостевую стеклянную плашку с входом и регистрацией. Сервер дополнительно проверяет владельца и сессию.
- Регистрация: имя/логин, email, пароль и повтор пароля. Вход выполняется по email и паролю; имя — отображаемое, не отдельный уникальный идентификатор входа.
- Для локального стенда включён MOCK_EMAIL=true. Автоподтверждение работает только при явном флаге и APP_ENV=development. Настоящие пароли хешируются, сессии серверные, cookie HttpOnly, изменения защищены CSRF. Это реальная локальная авторизация с моковой доставкой почты, а не пароль в localStorage.
- Имя и данные титульного листа сохраняются в БД через /auth/profile, восстанавливаются после входа/обновления. Миграция studio_profile применена. Email из серверного аккаунта доступен только для чтения.
- Добавлен выход с очисткой работ, баланса, профиля и текущего документа из состояния интерфейса.
- Формы входа/регистрации используют существующий FeaturedCard/border beam, обе цветовые схемы, подписи полей и autocomplete. Вставка паролей не блокируется.
- Нажатие «Составить план бесплатно» сразу открывает шаг «План» с существующей AiOrb и скелетонами. Уведомление «ждите здесь» удалено. План появляется автоматически; сбой показывает отдельное состояние с возвратом к параметрам.
- Модалка оплаты: сводка заказа, отдельная плашка тестового режима, карточки рублей/кредитов, доступный баланс/дефицит, итог и одна основная кнопка. Рубли подтверждаются на сервере без банковского запроса; недостаточные кредиты недоступны.
- Исправлены границы этапов прогресса (5/75/85/100%), сообщение о паузе из-за лимита, заголовок при terminal failure. Опрос прекращается в устойчивом состоянии; настройки не перезаписываются каждые 2,5 секунды.
- Уточнена инструкция для будущих AI-планов: исследовать именно topic, не превращать тему в инструкцию настройки аккаунта. Повторный live-тест этой последней правки не запускался ради экономии квоты.
- Скрипт остановки теперь завершает проверенный дочерний Python Windows venv, чтобы перезапуск действительно перечитывал код и конфигурацию. Посторонние процессы не останавливаются.

## Живая генерация и расход

Использован настроенный **Groq**, не Grok/xAI. Список моделей ответил 200 без генерации. Две ранние попытки плана получили 403. Контрольный план через тот же адаптер успешно вернул две главы за 327 reported tokens. После перезапуска worker третий план в приложении завершился за 377 reported tokens, затем один заказанный реферат на 8 страниц дошёл до конца основных разделов и остановился на заключении: ai_access_denied (HTTP 403). Был также один ai_timeout и штатные паузы для лимитов.

По успешным ответам: **5 128 reported tokens**, включая контрольный план. Консервативная серверная оценка документа выше (11 424), поскольку неизвестный расход таймаута резервируется. Это не точная сверка счётчика провайдера. Лимиты приложения не повышались, большие работы не запускались, платный fallback не подключался.

При сбое: состояние failed, 75%, order=simulated_refund, тестовый возврат 19900 копеек, реального payment_id нет, денег не списано. Файлы и 100% пользователю не обещаются. Доказательства: evidence/review-2026-11-02.json и review-generation-failure.png. Причина периодических 403 пока не установлена; это не доказательство неверного ключа или исчерпанной квоты.

## До публичного запуска

1. Устранить нестабильный доступ к chat/completions Groq из рабочего окружения. После этого повторить один полный живой заказ 8 страниц, проверить русский текст, источники, Word/PDF и фактический объём. Точное попадание в число страниц и академическое качество пока не приняты.
2. Привести исторические тесты к единому контракту и получить зелёный полный применимый набор. Не возвращать хранение временных текстов ради старого теста.
3. Реализовать production-конфигурацию/развёртывание. Сейчас cfg явно допускает только development/test, стенд закрыт private gate. Нужны домен/HTTPS, secure cookie, управление секретами, мониторинг, согласованный Linux/PDF runtime и проверка восстановления metadata. Текущий Word-конвертер зависит от Windows с установленным Word.
4. Подключить реальную отправку/подтверждение почты и пользовательский UI восстановления пароля. Серверный reset существует, текущая форма восстановления и смена email/пароля в кабинете ещё предварительные. OAuth-кнопки демонстрационные. Не включать MOCK_EMAIL на публичном сервисе.
5. После появления реквизитов подключить реальную ЮKassa, webhook/reconciliation/refunds и приёмочные платежи. Сейчас checkout намеренно моковый. Подготовить отдельную production-БД без тестовых начислений и заказов.
6. Данные титульного листа сохраняются в профиле, но текущий генератор документа их ещё не использует для полноценного вузовского титульника. Подключить их только на серверном этапе оформления, не передавать персональные данные LLM. Загрузка методичек сейчас не подключена.
7. Перед коммерческим запуском подготовить пользовательские документы, правила обработки данных/хранения и согласовать платёжные/учётные требования с профильными специалистами.

От владельца для текущего локального теста дополнительных ключей не нужно: можно зарегистрировать собственную тестовую почту и пароль (от 12 символов). Для следующей live-приёмки нужен стабильный доступ Groq; позднее — реквизиты ЮKassa, почтовый сервис, домен/сервер и требования к титульному листу/допуску по объёму. Производственную готовность процентом сейчас оценивать некорректно: ключевые блокеры перечислены выше.
