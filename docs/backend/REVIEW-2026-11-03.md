## Как подключить OpenRouter

1. Создать аккаунт и API key: https://openrouter.ai/settings/keys . Не вставлять ключ в чат, frontend или VITE_*.
2. Изменить корневой .env, оставив существующие DATABASE_URL, PROTOTYPE_KEY и другие параметры:

```dotenv
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=ваш_ключ_только_локально
OPENROUTER_MODEL=openrouter/free
```

3. Перезапустить API/worker:

```powershell
powershell -NoProfile -File scripts/prototype-run.ps1 -RestartBackend
```

4. Создать НОВЫЙ черновик на 3 страницы и две главы. Старые failed jobs автоматически не оживают и не меняют провайдера. Проверить план, mock checkout, завершение, скачивание обоих файлов, фактические страницы и содержание.
5. Для воспроизводимой проверки качества вместо случайного free router выбрать конкретный доступный model ID. Бесплатный router меняет модель и ограничен квотами. Лимиты аккаунта смотреть в кабинете или GET /api/v1/key; наличие бесплатной модели не означает гарантированную доступность.
6. Если бесплатные endpoint нестабильны, использовать OPENROUTER_MODEL=openai/gpt-oss-120b после небольшого пополнения и установки расходного лимита ключа. Модель платная: включать явно. На 03.11.2026 страница модели показывает цены от $0.024/M входных и $0.087/M выходных токенов, зависящие от endpoint. Например, 20k входных + 10k выходных ≈ $0.00135 только за токены по этим стартовым ставкам; reasoning, повторы, endpoint и комиссии меняют итог. Сверять стоимость в Activity.

Для частой проверки UI, очереди и файлов использовать явные TestAI/httpx.MockTransport из tests_prototype. Для оценки качества русского текста и источников нужен отдельный живой тест. Mock не должен попадать в пользовательский workflow как незаметный fallback.

## Регистрация и локальное хранение

Деплой для тестирования НЕ нужен. PostgreSQL на 127.0.0.1:55432, база gostdoc_proto, физические данные в .local/pgdata. Пользователи, хеши паролей scrypt с индивидуальной солью, серверные сессии и профиль сохраняются после перезапуска приложения. В браузере — HttpOnly cookie сессии; в БД хранится хеш её токена. Изменяющие запросы требуют CSRF.

MOCK_EMAIL=true в development позволяет тестировать регистрацию без почтового сервиса: это имитация подтверждения, не настоящая доставка. Служебные токены локального mail sink — .local/private/mail. Готовый текст и файлы временные: окно выдачи 24 часа, затем очистка; постоянными остаются metadata/учётные записи. .env и .local исключены из Git. Локальный PostgreSQL и private gate рассчитаны на личный стенд, не на публичный доступ.
